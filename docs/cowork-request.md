参加率アプリの画面がわ（クロードコード担当）です。
新しいデプロイURLを実際に叩いて確認しました。1件、直してほしいところがあります。

## 直してほしいこと：業者マスターの列がずれています

`?action=masters` の返りがこうなっています。

```json
{ "vendorId": "V01", "vendorName": "陽気", "yomi": "会員", "kubun": "" }
```

`yomi` に **「会員」（区分の値）** が入り、`kubun` が **空** になっています。
4件とも同じずれ方です（V04は `yomi:"執行部"` / `kubun:""`）。

シートの実際の列は

```
業者ID / 業者名 / 区分 / よみ
```

の順で、GASは

```
業者ID / 業者名 / よみ / 区分
```

のつもりで読んでいるように見えます。**よみ列を足したときに、
新しい列をどこに挿したかと、GASが読む列番号が食い違っています。**

## これが一番まずい理由：執行部の除外が効かなくなっています

`?action=summary` がこうなっています。

```json
{ "id": "V04", "name": "執行部A", "kubun": "会員", "judge": "−" }
```

**前のデプロイでは `kubun: "執行部"` / `judge: "対象外"` でした。**
`kubun` が空になったせいで「会員」に落ちてしまい、
執行部Aが召集判定の対象に入ってしまっています。

設計書7-2の

> 区分が「執行部」なら → 召集判定の対象外（回数は記録するが判定しない）

が効いていない状態です。ここはアプリの目的そのものなので、
実データを入れる前に直してください。

## 直しかた（どちらでもいいです）

- シートの列を `業者ID / 業者名 / よみ / 区分` に並べ替える、か
- GASが読む列番号を `業者ID / 業者名 / 区分 / よみ` に合わせる

直したあと、`?action=summary` で **V04（執行部A）の `kubun` が `"執行部"`、
`judge` が `"対象外"` に戻ること** を確認してもらえると確実です。

## ついでに：よみ列がまだ空です

列ずれを直しても、よみ列の中身が空のままだと
漢字ではじまる事業所は50音の「その他」に入ります。
ひらがなで埋めてください（例：陽気 → ようき）。

画面がわは **ひらがな・カタカナ以外が よみ に入っていたら無視する** ようにしてあるので、
いまの状態でも画面は壊れていません。埋まれば自動で正しく並びます。
